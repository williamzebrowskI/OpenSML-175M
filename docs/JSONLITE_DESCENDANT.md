## Native JSON descendant update

The JSONLite descendant is intended for short English extraction into a flat object with string, nullable-string or string-array fields. It can omit, merge or misassign values even when its JSON is valid. Nested/record schemas, numeric/Boolean outputs, optional-property logic and advanced schema rules are outside that released runner's verified scope. Its reported scores are specific to the documented evaluation panels. See the descendant model card's **Intended use and limitations** section before choosing it for an application; these statements do not describe new capabilities of the pretrained base.

The current [OpenSML-JSONLite-175M-Instruct](https://huggingface.co/OpenSML/OpenSML-JSONLite-175M) adds a joint full-weight JSON extraction SFT to its earlier grounded-QA, extraction and native JSON ancestry. The latest stage mixes original source/schema/JSON TRAIN replay, multiple-value examples and authored prose. The released main checkpoint inherits 19,200 presentations from a 21,144-presentation experiment. It directly generates the complete JSON object; validation follows without assembly or repair.

On the same previously observed 1,444-request SNIPS-derived evaluation, the descendant achieves **1,271/1,444 (88.02%) complete correctness**, **94.17% field accuracy**, **92.88% extracted-value F1**, **92.42% precision**, **93.35% recall**, **95.22% missing-field accuracy** and **100% schema validity**. The observed 60-case playground scores 49/60. Compared with the previous release, 96 requests improve and 24 regress. These are descendant results on repeatedly observed research panels, not scores of this base or a fresh blind benchmark. See the [current JSONLite technical report](https://huggingface.co/OpenSML/OpenSML-JSONLite-175M/blob/main/TECHNICAL_REPORT.md) for the full provenance, protocol and limitations.

The pretrained base weights, tokenizer, inference runner and source bundle are unchanged.
